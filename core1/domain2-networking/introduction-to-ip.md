## 概要

Domain 2（Networking）全体の土台となる内容。IPの仕組み、TCP/UDP の違い、ポート番号の概念、主要プロトコルのポート番号を理解する。

---

## 1. ネットワークの基本イメージ

ネットワークを「道路」に例えると：

| 例え | 実際 |
|------|------|
| 道路 | ネットワーク（Ethernet, Wi-Fi, DSL等）|
| トラック | IP（Internet Protocol）|
| トラックの中の箱 | TCP または UDP |
| 箱の中身 | アプリケーションデータ（HTTP, メール等）|

→ データは何層にも包まれて送られる。これを **カプセル化（Encapsulation）** と呼ぶ。

---

## 2. カプセル化の構造

```
[ Ethernet Header | IP Header | TCP Header | HTTP Data | Ethernet Trailer ]
```

- **Ethernet** — ネットワーク上でデータの開始と終了を示す
- **IP** — 送信元と宛先のアドレスを持つ
- **TCP/UDP** — データの配送方法を決める
- **HTTP等** — 実際のアプリケーションデータ

---

## 3. TCP vs UDP

### TCP（Transmission Control Protocol）

- **コネクション型** — 通信の開始と終了に正式な手順がある（電話と同じ）
- **信頼性あり** — データが届いたか確認（ACK = 受信確認）
- **再送機能あり** — データが壊れたら再送する
- **フロー制御あり** — 受信側が「速く/遅く」を指示できる
- **用途:** Web（HTTPS）、SSH、メール等

### UDP（User Datagram Protocol）

- **コネクションレス** — 開始・終了の手順なし。いきなり送る
- **信頼性なし** — データが届いたか確認しない
- **再送機能なし** — 壊れても再送しない
- **フロー制御なし** — 受信側は速度を制御できない
- **メリット:** オーバーヘッドが少ない → 高速
- **用途:** VoIP（音声通話）、動画ストリーミング、DHCP、TFTP

### 比較表

| | TCP | UDP |
|--|-----|-----|
| 接続方式 | コネクション型 | コネクションレス |
| 信頼性 | あり（ACK） | なし |
| 再送 | あり | なし |
| フロー制御 | あり | なし |
| 速度 | 遅め（確認が必要） | 速い（確認不要） |
| 用途 | Web, SSH, メール | VoIP, 動画, DHCP |

> **ポイント:** UDPでも、アプリケーション側で独自に再送を管理することは可能。TCP の機能を OS ではなくアプリが代替する形。

---

## 4. IPアドレス

- ネットワーク上の全てのデバイスに割り当てられる住所
- 家の住所と同じ役割 → データをどこに届けるか指定する
- 送信元IPと宛先IPの2つが必ず必要

---

## 5. ポート番号

IPアドレスが「家の住所」なら、ポート番号は「部屋番号」。

1台のサーバーで複数のサービスが動いている場合、ポート番号でどのサービスにデータを届けるかを区別する。

### ポートの種類

| 種類 | 範囲 | 説明 |
|------|------|------|
| Well-Known（非エフェメラル） | 0 〜 1,023 | サーバー側で使う固定ポート |
| エフェメラル（一時的） | 1,024 〜 65,535 | クライアント側で一時的に使うランダムポート |

### 重要な注意点

- TCP のポート 80 と UDP のポート 80 は **別物**（プロトコルが違う）
- ポート番号はセキュリティ機能 **ではない**（単なる参照番号）
- 通信には3つの情報が必要：**IPアドレス + TCP/UDP + ポート番号**

---

## 6. 通信の実例

```
サーバー (10.0.0.2)
├── Web Server    → TCP port 80
├── VoIP Server   → UDP port 5004
└── Email Server  → TCP port 143

クライアント (10.0.0.1) からの通信：

① Web通信:   src 10.0.0.1:48321 → dst 10.0.0.2:80    (TCP/HTTP)
② VoIP通信:  src 10.0.0.1:51444 → dst 10.0.0.2:5004  (UDP/VoIP)
③ メール通信: src 10.0.0.1:62881 → dst 10.0.0.2:143   (TCP/IMAP)
```

- 宛先ポート = Well-Known ポート（固定）
- 送信元ポート = エフェメラルポート（毎回ランダム）
- 通信が終わったらエフェメラルポートは破棄。次の通信では新しい番号を使う

## 7. Common Ports（頻出ポート番号）

ポート番号はファイアウォール設定やトラブルシューティングで必須。試験では暗記必須。

### ★ 必須暗記ポート一覧

| ポート | プロトコル | サービス | 説明 | 暗記のコツ |
|--------|-----------|----------|------|-----------|
| 20/21 | TCP | FTP | ファイル転送。20=データ転送、21=制御 | 「20-21歳でFTP（ファイル）初めて送った」 |
| 22 | TCP | SSH / SFTP | 暗号化されたリモート接続 / ファイル転送 | 「22でSecure Shell」 |
| 23 | TCP | Telnet | 暗号化なしのリモート接続（古い・危険） | 「23 = SSHの隣、でも暗号化なし」 |
| 25 | TCP | SMTP | メール送信（暗号化なし） | 「25でメールを Send（SMTP）」 |
| 53 | UDP | DNS | ドメイン名 → IPアドレスの変換 | 「53でDNS、名前解決」 |
| 67/68 | UDP | DHCP | IPアドレスの自動割当。67=サーバー、68=クライアント | 「67-68 でIP自動配布」 |
| 80 | TCP | HTTP | Webサイト閲覧（暗号化なし） | 「80 = Web」 |
| 110 | TCP | POP3 | メール受信（ダウンロード型、暗号化なし） | 「110 = POP（ポップ）でメール取り出す」 |
| 143 | TCP | IMAP | メール受信（同期型、暗号化なし） | 「143 = IMAP、複数端末で同期」 |
| 389 | TCP | LDAP | ディレクトリサービスへのアクセス（暗号化なし） | 「389 = LDAP、ユーザー検索」 |
| 443 | TCP | HTTPS | Webサイト閲覧（暗号化あり） | 「443 = セキュアWeb」 |
| 445 | TCP | SMB | Windowsファイル共有 | 「445 = Windowsのファイル共有」 |
| 587 | TCP | SMTP (Secure) | メール送信（暗号化あり） | 「587 = セキュアなメール送信」 |
| 993 | TCP | IMAPS | メール受信・同期（暗号化あり） | 「993 = セキュアIMAP」 |
| 995 | TCP | POP3S | メール受信・ダウンロード（暗号化あり） | 「995 = セキュアPOP3」 |
| 636 | TCP | LDAPS | ディレクトリサービス（暗号化あり） | 「636 = セキュアLDAP」 |
| 3389 | TCP | RDP | リモートデスクトップ（Windows） | 「3389 = リモートデスクトップ」 |

## 8. ★ セキュアなポート vs 非セキュアなポート（超重要）

試験で「secure session」「encrypted」と聞かれたら暗号化ありのポートを選ぶ。

| 非セキュア（暗号化なし） | ポート | セキュア（暗号化あり） | ポート |
|------------------------|--------|---------------------|--------|
| Telnet | 23 | **SSH** | **22** |
| HTTP | 80 | **HTTPS** | **443** |
| FTP | 21 | **SFTP（SSH経由）** | **22** |
| SMTP | 25 | **SMTP Secure** | **587** |
| POP3 | 110 | **POP3S** | **995** |
| IMAP | 143 | **IMAPS** | **993** |
| LDAP | 389 | **LDAPS** | **636** |

> **覚え方:** 「Sが付いたらSecure」— HTTPS, IMAPS, POP3S, LDAPS, SFTP

## 9. 各ポートの詳細

#### FTP（20/21）
- ファイルのアップロード・ダウンロード・削除・一覧表示ができる
- ユーザー認証が必要（匿名ログインも設定可能）
- ポート20がデータ転送、ポート21が管理・制御用

#### SSH（22） vs Telnet（23）
- SSH = 暗号化あり → **必ずこっちを使う**
- Telnet = 暗号化なし → **古いシステムにしかない、使うべきではない**
- 見た目や機能は同じ。違いは暗号化の有無だけ
- SFTP = SSH上でファイル転送（FTPのセキュア版）→ ポート22を使用

#### SMTP（25 / 587）
- メールを**送る**ためのプロトコル
- サーバー間のメール転送にも使われる
- 25 = 暗号化なし / 587 = 暗号化あり
- 受信はPOP3かIMAPを使う

#### DNS（53）
- `www.google.com` → `142.250.x.x` のように名前をIPに変換
- 超重要なサービス → 冗長化（複数サーバー）が一般的
- これが止まるとWebサイトが開けなくなる

#### DHCP（67/68）
- デバイスが起動時に自動でIPアドレスを取得する仕組み
- 配布するもの：IPアドレス、サブネットマスク、ゲートウェイ、DNSサーバー
- IPアドレスは「リース」（期限付き貸出）で管理される
- 特定デバイスに固定IPを予約することも可能（DHCP予約）

#### HTTP（80） vs HTTPS（443）
- HTTP = 暗号化なし（平文）
- HTTPS = 暗号化あり（今はほとんどこっち）
- ファイアウォールでは443を許可、80はブロックする場合もある

#### POP3（110 / 995） vs IMAP（143 / 993）
- POP3 = メールをサーバーからダウンロードして端末に保存。基本機能のみ
- IMAP = メールをサーバーに残したまま同期。複数端末で同じメールが見える
- **IMAPの方が高機能で現在の主流**
- 995 = POP3のセキュア版 / 993 = IMAPのセキュア版

#### SMB / CIFS（445）
- Windowsのファイル共有・プリンター共有に使われる
- 旧バージョンではNetBIOSが必要だった（UDP 137 / TCP 139）
- 現在はNetBIOSなしの直接通信（TCP 445）が主流

#### LDAP（389 / 636）
- ディレクトリサービス（ユーザー・デバイスのデータベース）へのアクセスに使用
- Microsoft Active DirectoryがLDAPを使っている
- 636 = LDAPのセキュア版（LDAPS）

#### RDP（3389）
- Windowsのリモートデスクトップ接続
- 画面共有してリモートからPCを操作できる
- Windows以外（Mac, Linux, iPhone）からもRDPクライアントで接続可能

---

## 10. グループ別暗記法

**メール系:** SMTP(25/587)で送る → POP3(110/995)かIMAP(143/993)で受け取る

**Web系:** HTTP(80) = 暗号化なし → HTTPS(443) = 暗号化あり

**リモート接続系:** SSH(22) = 安全 → Telnet(23) = 危険 → RDP(3389) = Windows用

**インフラ系:** DNS(53) = 名前解決 → DHCP(67/68) = IP自動配布

**Windows系:** SMB(445) = ファイル共有 → LDAP(389/636) = ディレクトリ

**ファイル転送:** FTP(20/21) = 汎用 → SFTP(22) = セキュア版
