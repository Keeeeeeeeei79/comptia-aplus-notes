## 概要

IPv4とIPv6のアドレス構造、パブリック/プライベートIPの違い、APIPA、IP割当方法を理解する。

---

## 1. IPv4（Internet Protocol version 4）

### 基本構造
- **32ビット** のアドレス（4バイト）
- 4つのオクテット（8ビットずつ）をドット（.）で区切る
- 例: `192.168.1.131`
- 各オクテットの範囲: **0 〜 255**

### 2進数表記
```
192      .168      .1        .131
11000000.10101000.00000001.10000011
```

### IP設定に必要なもの
1. **IPアドレス** — デバイスの住所
2. **サブネットマスク** — どのサブネットに属するか判定（例: 255.255.255.0）
3. **デフォルトゲートウェイ** — 別サブネットへの出口（ルーターのIP）
4. **DNSサーバー** — 名前解決用

---

## 2. パブリックIP vs プライベートIP

### プライベートIPアドレスの範囲（★暗記必須）

| クラス | 範囲 | アドレス数 |
|--------|------|-----------|
| Class A | 10.0.0.0 〜 10.255.255.255 | 約1600万 |
| Class B | 172.16.0.0 〜 172.31.255.255 | 約100万 |
| Class C | 192.168.0.0 〜 192.168.255.255 | 約65,000 |

- プライベートIP: ローカルネットワーク内でのみ有効（インターネットに直接出られない）
- パブリックIP: インターネット上で一意（ISPから割り当てられる）
- NAT（Network Address Translation）でプライベートIP → パブリックIPに変換してインターネットに出る
- 家庭のルーターは通常 **192.168.x.x** を使用

---

## 3. IPv6（Internet Protocol version 6）

### 基本構造
- **128ビット** のアドレス（16バイト）
- 8グループの16ビットずつ、コロン（:）で区切る
- **16進数**で表記
- 例: `fe80:0000:0000:0000:5d18:0652:cffd:8f52`

### IPv6の省略ルール
1. **先頭のゼロは省略可能:** `0652` → `652`
2. **連続するゼロのグループは :: で省略:** `fe80:0000:0000:0000:` → `fe80::`
3. `::` は1つのアドレスに**1回だけ**使用可能

### 省略例
```
完全形:  fe80:0000:0000:0000:5d18:0652:cffd:8f52
省略形:  fe80::5d18:652:cffd:8f52
```

### IPv4 vs IPv6 比較

| | IPv4 | IPv6 |
|--|------|------|
| ビット数 | 32ビット | 128ビット |
| 表記 | 10進数（ドット区切り） | 16進数（コロン区切り） |
| 例 | 192.168.1.1 | fe80::5d18:652:cffd:8f52 |
| アドレス数 | 約43億 | 約340澗（undecillion） |
| 設定 | 手動 or DHCP | 自動設定（SLAAC）が基本 |

## 4. IPアドレスの割当方法

### 動的割当（Dynamic / DHCP）
- DHCPサーバーからプールのIPを自動取得
- リース期間あり（期限切れで返却 or 更新）
- ほとんどのクライアントデバイスはこの方式

### 静的割当（Static）
- 手動でIPアドレスを設定
- サーバー、ルーター、プリンター等の固定が必要なデバイスに使用
- 変更が必要な場合、全デバイスを手動で更新する必要がある → スケーラブルではない

### DHCP予約（Reservation）
- DHCPサーバー側で特定デバイスに固定IPを設定
- デバイスのMACアドレスとIPアドレスを紐づけ
- 静的割当のメリット（固定IP）+ DHCP管理のメリット（一元管理）を両立
- IP変更時はDHCPサーバーだけ修正すればOK

---

## 5. APIPA（Automatic Private IP Addressing）

- DHCPサーバーからIPを取得できなかったときに、OSが自動で割り当てる仮のIP
- **範囲: 169.254.0.1 〜 169.254.255.254**
- 利用可能な範囲: 169.254.1.0 〜 169.254.254.255（最初と最後の256個は予約済み）
- APIPAではインターネットに接続できない（ローカル通信のみ）
- 割当前にARP（Address Resolution Protocol）で重複確認を行う

### 試験での頻出パターン
- ipconfigで `169.254.x.x` が表示 → **DHCPサーバーに問題がある**
- 正常なプライベートIP（192.168.x.x等）なのにインターネット不可 → DNS等の問題

### IPv6のリンクローカルアドレス
- IPv6にもAPIPAと同様のリンクローカルアドレスがある
- 範囲: `fe80::` で始まるアドレス
- すべてのIPv6対応インターフェースに自動割当
- ローカル通信用（ルーターを超えて通信はできない）

## 暗記チェックリスト

- [ ] IPv4 = 32ビット、4オクテット、10進数、各0〜255
- [ ] IPv6 = 128ビット、8グループ、16進数、:: で省略可能
- [ ] プライベートIP: 10.x.x.x / 172.16-31.x.x / 192.168.x.x
- [ ] APIPA = 169.254.x.x → DHCP失敗のサイン
- [ ] サブネットマスク = デバイスが自分のサブネットを判定するために必要
- [ ] DHCP予約 = MACアドレスとIPを紐づけて固定割当
- [ ] NAT = プライベートIP → パブリックIPに変換
- [ ] IPv6リンクローカル = fe80:: で始まる
